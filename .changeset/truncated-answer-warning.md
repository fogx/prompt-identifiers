An answer the model did not finish no longer reports its last placeholder as one the model invented. Under a format that opens a placeholder without closing it, such as `{ template: 'ID_{i:04}' }`, the cut lands mid-token and leaves `ID_000`. Nothing closes a placeholder in that format, so the scan reads the shortened digit run as a whole one and `unknown_placeholder` fired on every truncated answer, even though the format never writes a body that short. A token is now left alone when the model was stopped partway through, which means a finish reason of `length`, `content-filter` or `error`, a stream that was cancelled, or a stream that ended without reporting one at all, and a placeholder this call actually minted starts with it, which is what a cut leaves behind. A generated result missing its finish reason is read as complete rather than cut, because `doGenerate` returning at all means the answer finished; only a stream can end without saying so. Position is not part of the test, because an answer carrying several content blocks has one half-written placeholder per block. A token that starts none of them, such as an invented `ID_9999`, is still reported, and a format that closes its placeholders is unaffected either way because half of one is not a placeholder at all.

An example placeholder carrying `$` reaches the instruction intact. `{format}` was substituted with a string replacement, which reads `$$` as an escape, so `{ template: '$${i:03}$$' }` told the model to expect `$000$` while the prompt carried `$$000$$`.
